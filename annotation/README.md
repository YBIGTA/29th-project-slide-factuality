# annotation/ — 사람이 붙인 라벨

여기 있는 라벨이 이 프로젝트의 정답이다. 검색기 평가(B-1)도 판정 모델
학습(B-2)도 전부 이 파일에서 나온다.

## 파일

| 파일 | 무엇 |
| --- | --- |
| `공통_덱_annotation_정리본.xlsx` | 어노테이터별 시트. 사람이 보고 고치는 원본 |
| `annotations_long.csv` | 전 시트를 한 표로 합친 것. 코드가 읽는 쪽 |

시트 이름은 `{doc_id}__{어노테이터}` 다 (`arts_01__시나`). 생성기가 붙은
전체 `deck_id`(`arts_01__claudecode`)는 `_시트이름` 시트의 `레포 파일명`
열에 있고, `claims/` · `decks/` 파일과 맞출 때 그 값을 쓴다.

## 컬럼

| 컬럼 | 뜻 |
| --- | --- |
| `deck_id` | 어느 덱의 라벨인지. 시트 이름 앞부분과 같다 |
| `담당자` | **누가 붙인 라벨인지.** 시트를 CSV 로 뽑거나 행을 옮겨도 안 사라지도록 컬럼으로 박아 둔다 |
| `Slide #` | 슬라이드 번호 (정수) |
| `Claim (PPT)` | 판정 대상. `claims/{deck_id}.jsonl` 의 `Claim (PPT)` 와 글자가 같아야 한다 |
| `Slide_Title` | 그 슬라이드의 제목 |
| `Context (PPT)` | 슬라이드 전체 텍스트. 판정할 때 참고용 |
| `label` | `근거 있음` · `무근거` · `모순` · `Benign` 넷 중 하나 |
| `evidence_text` | **원문에서 복붙한 문장.** 아래 규칙을 지켜야 한다 |
| `ambiguity_note` | 판단이 갈릴 만한 이유를 적어두는 칸 |
| `확인요망` | `Y` 면 사람이 다시 봐야 한다 |

## evidence_text 규칙

`segment.find_evidence()` 가 이 문자열을 원문과 대조해서 근거 구간에 붙인다.
붙지 않으면 그 라벨은 **검색기 평가에서 통째로 빠진다.**

- 원문에서 드래그 → 복사 → 붙여넣기. 손으로 타이핑하거나 요약하지 않는다
- 문장 전체를 넣는다. `...` 로 중간을 생략하지 않는다
- `(p.131)`, `— 소제목` 같은 메모를 덧붙이지 않는다. 할 말은 `ambiguity_note` 에
- 근거가 두 문장이면 ` || ` 로 잇는다
- 머리말·각주에서 복붙하지 않는다. `docs/clean/` 에서 지워진 부분이라 안 붙는다
- `Benign` · `무근거` 는 근거가 없으므로 이 칸을 비운다

## 색

`label` 셀 색은 라벨값에서 자동으로 나온다. 손으로 칠하지 않는다.

```
근거 있음 연두   무근거 분홍   모순 노랑   Benign 회색   4분류 아님·빈칸 빨강
```

빨강이 보이면 그 셀은 아직 안 끝난 것이다. 표시해 둘 일이 있으면
`확인요망` 칸에 `Y`, 이유는 `ambiguity_note` 에 적는다.

## 자료가 있는지

`_시트이름` 시트 오른쪽에 `원문 PDF` · `정제 텍스트` · `덱 PPTX` · `manifest`
네 칸이 있다. **분홍(X)이면 라벨만 있고 원문이 레포에 없다는 뜻**이고, 그
덱은 검색기 평가(B-1)도 데이터셋 생성(B-2)도 못 돌린다.

```bash
python src/stamp_annotation.py      # 담당자 기입 + 자료 유무 갱신
```

레포에 파일을 추가한 뒤 이걸 다시 돌리면 O/X 가 갱신된다.

슬라이드 번호형 · 따옴표 · 색을 통일하고, 자동으로 못 고치는 행은 지우지 않고
