# 모델 비교 — test 셋 vs generalization(재무) 셋

네 모델을 **같은 스크립트·같은 가중치**로 두 셋에 각각 돌렸다 (`src/eval_generalization.py`).

| 셋 | 구성 | 행 수 |
| --- | --- | ---: |
| test | `arts_03` · `bio_04` · `socio_04` · `tech_04` | 283 |
| generalization | `finance_01`~`finance_05` (미지 분야 = 재무) | 538 |

두 셋 모두 라벨이 4분류가 아닌 행은 뺐다.

## 1. 도메인이 바뀌면 얼마나 떨어지는가

| 모델 | test macro-F1 | generalization macro-F1 | 하락 | 하락률 | test 정확도 | gen 정확도 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| M1 (frozen e5 + LinearSVC) | 0.4018 | 0.3033 | −0.0985 | −25% | 0.6926 | 0.5651 |
| M2 (KLUE-RoBERTa, 맥락 없음) | 0.2492 | 0.2090 | −0.0402 | −16% | 0.6996 | 0.5836 |
| M2' (동일 백본 대조군) | 0.2467 | 0.2017 | −0.0450 | −18% | 0.6254 | 0.4238 |
| M3 (KLUE-RoBERTa, 맥락 포함) | 0.2743 | 0.1740 | −0.1002 | −37% | 0.6855 | 0.4591 |

두 셋 모두 **M1 (frozen e5 + LinearSVC)** 가 가장 높다. 맥락을 넣은 M3 가 대조군 M2' 보다 나아지지 않는다는 점도 두 셋에서 같다 — 맥락 추가가 이 과제에서 도움이 되지 않았다는 뜻이다.

## 2. 클래스별 F1 — 무너지는 곳은 정해져 있다

| 모델 | 근거있음 test / gen | 무근거 test / gen | 모순 test / gen | benign test / gen |
| --- | ---: | ---: | ---: | ---: |
| M1 (frozen e5 + LinearSVC) | 0.817 / 0.710 | 0.196 / 0.109 | 0.087 / 0.100 | 0.507 / 0.295 |
| M2 (KLUE-RoBERTa, 맥락 없음) | 0.822 / 0.765 | 0.000 / **0.000** | 0.133 / 0.071 | 0.042 / **0.000** |
| M2' (동일 백본 대조군) | 0.788 / 0.692 | 0.091 / 0.061 | 0.071 / 0.054 | 0.036 / **0.000** |
| M3 (KLUE-RoBERTa, 맥락 포함) | 0.811 / 0.658 | 0.000 / **0.000** | 0.000 / **0.000** | 0.286 / 0.038 |

정답 분포

| 셋 | 근거있음 | 무근거 | 모순 | benign |
| --- | ---: | ---: | ---: | ---: |
| test | 201 | 25 | 14 | 43 |
| generalization | 316 | 47 | 22 | 153 |

**generalization 에서 F1 이 0 인 (모델, 클래스) 조합이 3개다.** M2 (KLUE-RoBERTa, 맥락 없음)의 '무근거', M3 (KLUE-RoBERTa, 맥락 포함)의 '무근거', M3 (KLUE-RoBERTa, 맥락 포함)의 '모순'.

이게 이번 평가의 핵심이다. 정확도가 0.42~0.58 로 보이는 것은 대부분 '근거있음' 을 찍어서 나온 수치이고, **환각 탐지에서 정작 잡아야 할 '무근거'·'모순' 은 거의 못 잡는다.** M3 의 혼동행렬이 그것을 보여준다.

```
M3 · generalization  (행=정답, 열=예측)
               근거있음      무근거       모순   benign
근거있음            244        0       72        0
무근거              43        0        4        0
모순               22        0        0        0
benign          117        0       33        3
```

'무근거' 열이 통째로 0 이다 — 한 번도 예측하지 않았다. '모순' 은 여러 번 예측했지만 맞힌 것이 없다.

## 읽을 때 주의할 것

1. **PR #10 은 아직 머지되지 않았다.** 예린님이 올린 259행 (`finance_01`+`02` 만, sha12 `4a3f556253bf`) 결과 `M3_test_everything.json` · `M2p_test_everything.json` 은 브랜치 `M3_new_json` 에 그대로 있다. 이 표의 숫자와 **다른 평가 셋**이므로 섞어 읽으면 안 된다.

2. **단일 seed 다.** 확보된 가중치가 모델당 한 벌뿐이라 3-seed 평균·표준편차를 낼 수 없다. 259행 결과(M3 0.1979 ± 0.0420)는 seed 13/42/777 세 벌의 평균이므로 이 표와 **직접 비교하면 안 된다**. 참고로 그 결과의 run[0] 단독값은 0.2483 으로, 시드 간 편차가 작지 않다.

3. **M2 의 입력 조립은 가정이다.** M2 는 코랩에서 학습했고 학습 코드가 레포에 없다. 그래서 입력 조립을 M3 형식으로 가정해 돌렸다. 실제 학습 때 쓴 형식과 다를 수 있으므로 **M2 수치의 정확도는 보증되지 않는다.** 이전 test 평가에서도 커밋값 0.426 과 재현값 0.482 가 벌어진 전례가 있다.

4. **test 수치는 누수를 걷어낸 뒤 다시 잰 값이다.** 이전 `model_compare.md` 의 277행 표는 `tech_04` 69행이 `train` 의 `tech_03` 과 글자 단위로 같던 시절의 것이라 위로 부풀려져 있었다. 커밋 `aafbf06` 에서 고쳐졌고, 이 표는 고친 뒤의 283행으로 다시 돌린 결과다.

5. **`finance_03`·`finance_05` 의 원문 정제는 사람 검수 전이다** (종결어미 비율 49.7% / 54.9%). 표·참고문헌이 섞인 초벌 상태로 passage 가 만들어졌다.

6. **`finance_04` 는 이번에 파이프라인을 새로 완성했다.** 직전까지 `docs/clean` 부터 검색 결과까지 전부 없어서 64행 전원이 근거 구간 없이 평가될 뻔했다. earticle PDF 가 심어둔 읽기 순서 텍스트 레이어를 쓰는 추출 방식을 추가해 26.2% → 75.7% 로 올린 뒤 검색까지 돌렸다.

7. **후보 구간이 비어 있는 행이 17개 남아 있다** (3.2%, `finance_03` 9 · `finance_05` 8). 어노테이션이 `claim_split.py` 보다 잘게 쪼갠 항목이라 대응하는 검색 결과가 아예 없다. 그 행들은 원문 근거 없이 판정된다.

8. **LLM 베이스라인은 이 표에 없다.** `results/judgments/*.tsv` 는 test 셋 4개 덱만 있고 재무는 판정한 적이 없다. 재무까지 비교하려면 LLM 판정을 먼저 만들어야 한다.
